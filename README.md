# 決算コンパニオン

元の適時開示アラートから独立した決算解析アプリです。このリポジトリだけを変更します。

**現状：ブラウザ受入テスト未完了。最終版ではありません。**

## 起動

Node.js 22以上を使用します。

```sh
npm ci --include=dev
npm run vendor
npm start
```

既定ポートは8790。Renderでは `PORT` に従います。ブラウザでは `/` を開きます。金額・PDFは外部AIへ送信せず、PDF.jsでブラウザ内解析します。

## 取得と解析

- `POST /api/earnings/sources`：銘柄・決算期・Qから候補を探索。候補は未確認のまま扱い、ブラウザでPDF先頭のコード・社名・決算期・Q・決算短信タイトルを照合して初めて採用します。
- `GET /api/pdf?url=...`：生PDFバイト専用プロキシ。Markdown変換やJina Readerは数値解析に使用しません。
- `GET /api/disclosures?ticker=7282&date=2026-10-29`：公式IRと同日のTDnet全ページを照合。全ページ取得を確認できない場合、公表なしと断定しません。
- Q2/Q3/Q4は今回累計と前Q累計を差し引きます。前年も各PDFの比較前年列を優先し、必要な場合だけ追加PDFを指定できます。
- セグメントは正式な報告セグメント表の列位置・単位・連結営業利益との整合性が確認できる場合に限定します。内部売上を含むセグメント売上を使います。
- 配当は配当表だけを解析し、分割時は明記された換算額のみ採用します。不確かな項目は欠損として保持します。
- PDF.js本体・Worker・CMapsとTesseractのローダーは `npm run vendor` で固定バージョンから同梱し、外部CDNへの依存を避けます。

自動探索はEIR配信、デンソーのXJ、NSK・スズキの公式資料ページ、当日のTDnetに対応しています。対応できない配信形式・過去資料はURLかPDFの直接指定を使用します。すべての会社・決算期・PDF形式に対応したとの保証はありません。

## IRサイト登録と説明会資料

会社IRの決算資料ページを銘柄ごとに登録できます。「登録IRから最新」を実行すると候補から対象期を選び、短信本文でコード・会社名・期・Qを照合します。最新期を確認できないサイト形式は採用を止め、直接指定へ案内します。HTML、EIR、XJの配信形式に対応し、すべてのIRサイトのJavaScript実行には対応していません。

「説明会資料の増減要因・セグメント分析」を選ぶと、今回・前Qと必要に応じて前年本決算の説明会資料を追加します。3種類ともURL又はPDFファイルで直接指定できます。

- 同じ分類のYoY増減図だけを累計−前Q累計で差し引きます。
- 通期の従来予想比とYoYは別の基準として扱い、根拠のない変換を行いません。
- セグメント計画変更は正式セグメント名と明記された旧・新計画を照合します。
- 数字が画像になっている図はブラウザ内のTesseractで読み、符号・合計・短信の営業利益との整合性を確認します。画像やPDFをAIサービスへ送信しません。エンジンと学習データは固定URLから同一オリジンの`/ocr/`経由で取得します。
- ページ番号と計算方法を残し、分類が変わった場合や読み取りを確信できない場合は、必要資料と算出できない理由を表示します。

## 検証

```sh
npm run check
npm test
```

テストは公式の生PDFをダウンロードして `.test-cache/` に一時保存します。既存キャッシュを使う場合は `EARNINGS_PDF_CACHE` にそのディレクトリを指定します。テストは実際のクライアントの計算・文章生成関数を読み込みます。別実装による期待値の再計算だけではありません。

7282/6902のQ2、6471/7269のQ1、コード・年度・Q誤指定、異常値、欠損、赤字表現について16件の回帰テストを実行しています。これらは**ブラウザE2Eテストの代替ではありません**。

ブラウザ検証の実施状況と残件は [QA_STATUS.md](QA_STATUS.md) を参照してください。
